    Bound processing, not useful lifetimes.

    Strict input validation can coexist with durable messages and evolving applications.

    V1 / Generation 1 — Candidate, PARTIAL. This revision changes the security transcript. Formal proof requalification is required; new-session eligibility is false and the Protocol Line is publication ineligible. Standard Nostr messaging remains a separate upstream contract. Definition tests do not establish deployed client support.

    Explicit record grammars

    Native runtime records use deterministic CBOR and governance uses restricted canonical JSON. The Nostr binding adds its own canonical envelope without redefining the native protected bytes. Exact parsing and key-purpose rules remain mandatory.

    Every field has a reason

    The field registry records the scope, representation and visibility of admitted fields. Removed prekey date labels are reserved rather than reused. Live capability, sync and group-resolution messages have explicit closed schemas.

    Deterministic source closure

    The definition refresh command rebuilds source closures, semantic identities, declared fixture context and generated bundles. It does not rewrite expected test outcomes from the model under test and it cannot regenerate a valid proof from a superseded formal theory.

    Reject invalid input; preserve valid pending work

    A malformed record, bad signature or revoked execution permission remains rejected. A missing predecessor, unavailable route or exhausted processing turn is a recoverable condition. Already accepted messages are not silently deleted to release memory. Frame and cryptographic bounds remain; pending data can be paged to durable storage under explicit quotas.
