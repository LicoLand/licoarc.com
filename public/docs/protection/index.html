    Offline establishment needs offline-safe state.

    The primitives remain, but the changed transcript requires new security evidence.

    V1 / Generation 1 — Candidate, PARTIAL. This revision changes the security transcript. Formal proof requalification is required; new-session eligibility is false and the Protocol Line is publication ineligible. Standard Nostr messaging remains a separate upstream contract. Definition tests do not establish deployed client support.

    Preserved primitive construction

    The Candidate retains paired X25519 and ML-KEM-768 one-time prekeys, Ed25519 and ML-DSA-65 authentication, and the X25519 Double Ratchet construction. This is a definition, not a claim that a deployed composite has been audited.

    Active authorization, not calendar expiry

    The revised prekey record has no validFrom or validUntil field and no seven-day age rule. Each pair must be genuinely issued, still active under accepted authority, correctly signed and atomically consumed only once. Unresolved asynchronous exchanges retain the material they need; a relay cannot manufacture a prekey or declare one safe.

    New transcript, explicit requalification

    Removing signed fields changes transcript identities even though V1 remains V1. Prior proofs and vectors remain inspectable as superseded evidence; they are not rebound to the new bytes. A new positive dual-signature first-packet vector and formal analysis of delayed active-prekey admission remain required.

    Recover delays without weakening replay protection

    Ciphertext may arrive far ahead of earlier records. Working limits on skipped-key derivation remain, but a valid pending message is retained and missing history is recovered rather than assigned a message lifetime. Atomic receive persistence preserves authenticated payload and replay state together. Key deletion must not strand the only authorized copy needed by unresolved work.
