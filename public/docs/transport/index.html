    HTTPS transport: a carrier without authority

    The Transport Profile fixes HTTP/2 over TLS 1.3 operations, resource accounting, retry outcomes, and residual metadata while carrying opaque protected packets.

    SOURCEHTTPS Transport Profile v1

    Fixed carrier

    Every operation uses HTTP/2 over TLS 1.3 with canonical content length and a lowercase operation identifier. The profile forbids alternate HTTP versions, early data, content coding, transfer encoding, trailers, query parameters, fragments, and streaming request bodies.

    Five operations

    OperationPurposeAccepted HTTP result
    AFFILIATEEstablish bounded Endpoint affiliation state201
    RESERVEReserve one bounded delivery handle201
    SUBMITSubmit one raw protected packet202
    CLAIMClaim bounded opaque packets200
    SETTLESettle transport ownership200

    Body and outcome authority

    HTTP, TLS, a certificate issuer, and the Station do not define protocol meaning. A successful Station response cannot substitute for authenticated Endpoint confirmation or authorize application effects.

    Exact resource accounting

    Storage, claim, settlement, body sizes, retry classes, and residual metadata are explicitly bounded. Rejection or ambiguous transport outcomes cannot advance protected Endpoint state by inference.
