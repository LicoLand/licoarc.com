    3. HTTPS transport

    A transport carries; custody persists.

    Native HTTPS remains independently usable. Nostr is an additional adapter, not a prerequisite.

    V1 / Generation 1 — Candidate, PARTIAL. This revision changes the security transcript. Formal proof requalification is required; new-session eligibility is false and the Protocol Line is publication ineligible. Standard Nostr messaging remains a separate upstream contract. Definition tests do not establish deployed client support.

    An independent native carrier

    The HTTPS Station target retains HTTP/2 and TLS 1.3 framing. Its transport security is not an Endpoint trust decision. Applications can use at least one authorized independent carrier without installing Nostr or federation governance.

    Five transport operations

    AFFILIATE, RESERVE, SUBMIT, CLAIM and SETTLE keep distinct purposes. A successful custody admission follows recoverable persistence. A claim temporarily assigns a worker; settling completes or releases the claimed items according to the protected delivery contract.

    Custody is not Endpoint acceptance

    A Station receipt never proves that the recipient has durably received, read, approved or executed anything. The sender and any authorized custodians retain responsibility until the contract allows release or verified transfer; no transport hint alone upgrades application finality.

    Lease expiry releases occupancy, not the message

    The one-hour storage lifetime and five-minute idempotency expiry are removed. The 300-second claim lease remains only to release a stalled worker’s occupancy. Pending items and duplicate guards survive it. Reject or backpressure new submissions before promising storage when quota is full; do not age-evict accepted undelivered messages.
